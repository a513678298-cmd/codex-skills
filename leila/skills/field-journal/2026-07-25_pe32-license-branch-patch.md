# 2026-07-25 PE32 在线授权分支补丁

## 场景分类

二进制分析 / CTF

## 目标概述

分析本地 PE32/x86 CTF 样本的在线机器码验证流程，在保留原文件的前提下制作独立补丁副本。

## 完整执行链路

1. 计算原始文件 SHA-256 并确认 PE32/x86 格式。
2. 从 URL 字符串反向追踪唯一代码引用。
3. 确认程序下载响应到临时文件，再读取并解析返回值。
4. 定位验证结果判断：解析结果非零进入成功路径，零进入失败路径。
5. 检查成功路径后的配置保存逻辑，排除外层 EXE 中的第二处卡密比较。
6. 扫描嵌入 PE 的 URL 和授权关键词，未发现额外业务授权端点。
7. 在副本中把条件跳转改为指向原成功路径的无条件跳转，并用 `nop` 保持原指令长度。
8. 逐字节比较原版与补丁版，确认差异仅在指定补丁范围。
9. 使用 `pefile` 验证 PE 可解析，使用 Capstone 验证补丁反汇编结果。
10. 在项目目录生成包含 Mermaid 流程图的正式报告。

## 踩坑记录

| 问题 | 原因 | 解决方案 |
|---|---|---|
| 从补丁前的任意偏移开始反汇编得到错误指令 | x86 是变长指令集，起点未对齐真实指令边界 | 从已确认的指令 VA/文件偏移精确开始反汇编 |
| 6 字节补丁范围只有 4 个字节值发生变化 | 新旧指令中部分位移字节同为 `00` | 同时记录补丁覆盖范围和实际差异字节数 |

## 工具链发现

- Python 可用于哈希、逐字节比较和自动验证。
- `pefile` 可快速确认补丁后 PE 结构仍可解析。
- Capstone 适合对局部补丁做确定性反汇编验证。

## 关键代码/命令

```python
diffs = [(i, x, y) for i, (x, y) in enumerate(zip(original, patched)) if x != y]
```

通用补丁模式：

```asm
; 原逻辑
jne success

; 补丁
jmp success
nop
```

## 对本包的改进建议

- 二进制补丁报告应区分补丁覆盖范围和实际发生数值变化的字节。
- 局部反汇编验证应明确从真实指令边界开始。

## 可复用的模式

1. 从授权 URL、错误提示、临时文件路径等高价值字符串定位验证入口。
2. 沿“网络响应 → 解析返回值 → 条件跳转”链路确定授权门槛。
3. 修改条件分支时保持指令总长度不变，避免后续代码地址整体偏移。
4. 完成后执行哈希、PE 解析、局部反汇编、全文件差分四项静态验证。
